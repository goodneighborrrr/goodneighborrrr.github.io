# 英語口說練習 — 這個資料夾是什麼

網址：https://goodneighborrrr.github.io/speaking/ 。跟根目錄的單字 App 用同一個 Firebase 帳號、同一組登入密碼、同一組 Google AI 通行碼（Gemini API Key）。推送到 `main` 後，GitHub Pages 大約 1 分鐘內會更新，跟根目錄那個 App 一樣。

## 這個功能在做什麼

1. 按一下麥克風按鈕，瀏覽器開始聽（用瀏覽器內建的語音辨識，免費，不用申請任何東西）。
2. 一邊說話一邊即時把聽到的字顯示出來。
3. 說「that's it」（或按「這輪說完了」）結束這一輪。
4. 把這輪說的話送給 Gemini，請它回兩件事：
   - 把這句話改成自然、正確的英文，並用簡單的中文說明改了什麼、為什麼。
   - 像朋友聊天一樣，接著用英文回一句話，延續對話。
5. 畫面上顯示：原句、修改後的英文＋中文說明、AI 的回話；還可以按喇叭圖示請瀏覽器唸出來。
6. 自動接著聽下一輪，直到按「結束對話」。

## 重要決定：沒有用 Firebase Cloud Function，直接在瀏覽器呼叫 Gemini

一開始的想法是做一個 Firebase Cloud Function 當「中間人」，Key 放在後端，前端看不到。後來決定**不這麼做**，原因：

- **Firebase 的 Cloud Function 只要是會對外連線的（例如呼叫 Gemini），就一定要升級到「Blaze」付費方案**（要在 Firebase 綁一張信用卡），就算實際用量在免費額度內、沒有真的扣款，也要先綁卡。這跟主人「永遠不要花錢、不要訂閱」的原則有衝突，所以沒有照最初的計畫做。
- 這個單字 App 本來就已經有免費又安全的做法了：主人自己去 Google AI Studio 申請一組免費的 Gemini 通行碼，貼在單字 App「單字庫 → 設定」裡，存在**只有主人自己能讀寫**的雲端資料（Firestore，`users/{uid}` 這份文件的 `aiKey` 欄位，受登入保護）。單字 App 新增單字時就是這樣直接在瀏覽器呼叫 Gemini的。這個口說練習功能照同一套做法：**讀同一個欄位、用同一組通行碼，直接在瀏覽器呼叫 Gemini**，不用另外設定，也完全不花錢。
- Key 不會出現在原始碼或 git 裡——它只存在主人自己登入後、瀏覽器跟 Firebase 之間；跟任何沒登入的人都看不到。

如果以後真的想要「後端擋在前面、瀏覽器完全看不到 Key」這種更嚴謹的做法，那就要：
1. 到 Firebase 後台把 `eq-vocab-app` 專案升級成 Blaze 方案（綁信用卡，但只要用量在免費額度內就是 $0）。
2. 用 `firebase functions:secrets:set GEMINI_KEY` 把 Key 存成 Secret（不會進 git）。
3. 寫一個 Cloud Function 當 Gemini 的代理。

在那之前，目前這個直接呼叫的做法已經是免費、夠安全、而且跟單字 App 原本的習慣一致的方案。

## 為什麼 AI 回覆要「4 個版本同時問」

一開始是像單字 App 一樣，4 個 Gemini 版本一個一個輪流試、失敗才換下一個，每個中間還會等個 1-2 秒再重試。這樣最差的情況會疊加到快 30 秒，對「講話聊天」來說太慢、等起來會像當機。

改成**同時發送 4 個版本的請求**，誰先回來、誰成功就用誰，其他的直接不管。這樣最慢也只要等「最快那個」的時間，通常幾秒內就有結果。單字 App 那邊是「新增單字」，不急，所以還是維持原來一個一個試的做法，沒有改。

## iPhone（Safari）上的語音辨識，已知的狀況

- iOS 14.5 之後的 Safari 才支援語音辨識（用 `webkitSpeechRecognition`，不是標準名稱 `SpeechRecognition`，程式碼裡兩個都有判斷）。
- 雖然程式碼設定了「連續聽」（`continuous = true`），但 **iPhone 的 Safari 常常自己在停頓幾秒後就把它停掉**，不管有沒有設定連續聽——這是已知的瀏覽器限制，不是這個 App 寫錯。
- 解決辦法：程式碼裡有自動重開的機制——只要對話還在進行、這一輪還沒結束，瀏覽器自己把語音辨識停掉的話，就會自動重新開始聽，讓使用者感覺是「一直在聽」，不會中斷。
- 另外也保留了「這輪說完了」這個按鈕，就算說「that's it」沒被聽清楚，也可以直接按按鈕結束這一輪——這是題目要求的保險做法。
- AI 唸回覆的時候（`speechSynthesis`）會先把麥克風關掉，唸完才繼續聽，否則手機可能會把 AI 自己的聲音錄進去、誤判成使用者在說話。
- 電腦上的 Chrome／Edge 支援度比較好、比較穩定；Firefox 目前不支援這個語音辨識功能（網頁會顯示提示訊息）。

## 還需要主人做的事

目前這個功能可以直接用，不需要再設定什麼——只要單字 App 的「AI 通行碼」已經貼過，口說練習這裡就會自動讀到同一組。

如果以後想换成「後端代理」的做法（上面提到的 Cloud Function），那一步（升級 Blaze、綁信用卡）只有主人自己能做，Claude 不能代替她操作 Firebase 帳單設定。
